# Team-Vorlieben

Festgehaltene Vorlieben, damit Zusammenarbeit reibungslos läuft.

- Kommunikation kurz und konkret: was, warum, wie — in wenigen Sätzen.
- Kleine, nachvollziehbare Schritte; vor Code-Änderungen ein Branch.
- Tests gehören zu jeder Änderung dazu ([[feedback-testing-strategy]]).
- Keine Secrets im Code oder in Logs ([[feedback-secrets-hygiene]]).

Diese Vorlieben fließen ins Onboarding ein ([[user-onboarding-notes]]) und prägen
das CLI-Design ([[reference-cli-design]]).
